# Phase 0 黄金任务与验收基线

更新日期：2026-09-30

## 使用方式

每次版本冻结后执行以下任务。记录：任务状态、耗时、人工干预次数、工具失败次数、验证结果、产物路径和是否可恢复。测试结果应区分：

- 本地回放通过
- 真实环境通过
- 未执行（需要凭据或系统权限）

## 任务清单

| ID | 任务 | 主要能力 | 通过标准 |
|---|---|---|---|
| G01 | 分析当前项目结构并给出改进建议 | 只读文件、搜索、总结 | 不修改文件，输出路径和风险清单 |
| G02 | 修改单个文件并运行对应测试 | 文件写入、Diff、验证 | 写入可审计，测试结果可见 |
| G03 | 跨文件重构并检查类型 | 多文件编辑、验证计划 | 变更完整，无未解释的失败 |
| G04 | 修复一个已知失败测试 | 终端、测试反馈、迭代修复 | 失败日志反馈给 Agent，最终结果真实 |
| G05 | 用户拒绝一次权限请求 | 权限状态机、恢复 | 任务进入可继续状态，不伪造失败或成功 |
| G06 | API 401/Endpoint 错误 | Provider 健康检查 | 显示具体原因和可操作修复建议 |
| G07 | MCP Server 调用与崩溃恢复 | MCP、权限、故障注入 | 崩溃无挂起，任务可重试或降级 |
| G08 | Git Worktree 隔离任务 | Worktree、分支、清理 | 成功时隔离，失败时明确回退原因 |
| G09 | 应用中途退出后恢复 | Intent、Receipt、恢复 | 已结算不重放，未结算不伪造成功 |
| G10 | 创建 PR 并等待 CI | gh、PR/CI、通知 | PR 状态与 CI 状态不混淆 |

## 发布门槛

- 不允许出现界面显示完成但没有 Receipt 或验证结果的任务。
- 高风险动作必须经过授权。
- 重启恢复不得重复执行已结算外部副作用。
- API、MCP、浏览器和 Computer Use 的本地回放与真实验收必须分开标记。
- 失败必须给出下一步动作：继续、重试、回滚、清理或导出诊断。
